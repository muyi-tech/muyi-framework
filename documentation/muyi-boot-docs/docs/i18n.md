# 错误码与国际化

muyi-boot 的错误码注册表承担**码值 → 多语言文案**的解析与来源分层管理，
与[异常处理指南](exception-handling.md)、[错误码分配表](error-codes.md)配套。

## 架构一览

```
ErrorCodeProvider（SPI，多来源）            DefaultErrorCodeRegistry
  ConstantsErrorCodeProvider（框架 12 码）    volatile 快照，读路径无锁
  FileErrorCodeProvider（locations 文件）     写路径持锁构建新快照 → 原子替换
  业务自定义 Provider（DB/Redis/Nacos…）       重复码按 OverridePolicy 处理
```

来源按 `Ordered` **降序**加载（值越大越先注册）：常量源最先兜底、文件源随后、
业务自定义最后——配合 `LAST_WINS` 形成"越靠近业务的来源话语权越大"。

## 配置键

| 键 | 默认值 | 说明 |
|----|--------|------|
| `muyi.error-code.locations` | 空 | 错误码定义文件位置列表，支持 `classpath:` 与 `file:` 前缀，后加载者覆盖前者 |
| `muyi.error-code.override-policy` | `LAST_WINS` | 重复码策略：`LAST_WINS` 覆盖（WARN 日志）/ `FIRST_WINS` 保留先者 / `REJECT` 启动期抛异常 fail-fast |

文件形态（YAML）：

```yaml
# src/main/resources/errorcodes/biz.yaml
error-codes:
  - code: 1001001000
    msg: "用户 {} 不存在"
    messages:
      zh-CN: "用户 {} 不存在"
      en-US: "User {} does not exist"
  - code: WECHAT_API_ERROR          # 字符串码同样支持
    msg: "微信接口调用失败: {}"
```

## i18n 解析

异常处理器在构造 `ApiResult` 前按**请求 Locale**（WebMVC 经 `LocaleContextHolder`、
WebFlux 经 exchange 的 `LocaleContext`，均为框架请求级解析结果）逐级回退取文案：

1. 精确语言-国家（`zh-CN`，BCP 47 连字符形态）
2. 语言级（`zh` / `en`）
3. 错误码登记时的默认 `msg`

消息模版 `{}` 占位符在取到本地化模版后，用 `ServiceException.getArgs()` **重新格式化**——
这就是业务异常要求携带 args 的原因（异常跨进程传播时，`ApiResult.checkError()` 重建的
异常不含 args，模版会原样输出，见[已知限制](#_6)）。

## 业务码登记（双轨约定）

业务方的代码常量（如 `UserErrorCodeConstants`）**不会自动进注册表**——框架不扫描业务
类路径（边界清晰、无启动期反射成本）。异常照常抛出（message 自带），但若要该码参与
**i18n 翻译**，必须把定义同时写入 `locations` 文件（或自实现 `ErrorCodeProvider` 注册
为 Bean）；否则行为降级为默认 msg 单语输出。

## 热更新与刷新

- `DefaultErrorCodeRegistry#reload()` 重新聚合全部来源并原子替换快照，
  读线程要么看到完整旧快照、要么看到完整新快照，无中间态；
- reload 完成后发布 `ErrorCodeReloadedEvent`，业务侧可监听做缓存预热等联动；
- 动态来源（DB/Nacos Provider）由业务方自行调用 `reload()` 触发（P2 提供管理端样例）。

## 数字码规范化

注册时数字码统一为**十进制无前导零**形态（`"500"` 而非 `"0500"`），保证同一码值
全集群唯一形态；字符串码按原样使用（`MUYI_` 前缀为框架保留，业务禁用）。

<a id="_6"></a>

!!! note "已知限制（跨进程 args）"

    `ApiResult` 不承载格式化参数（args）：RPC 响应经 `checkError()` 重建的
    `ServiceException` args 为 null，远端 i18n 重格式化会退化为模版原样输出。
    需要跨进程完整本地化时，请让调用方携带完整 ErrorCode 定义或透传 args（P2 议题）。
