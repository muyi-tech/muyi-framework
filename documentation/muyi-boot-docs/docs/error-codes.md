# 错误码分配表

框架错误码的**唯一权威分配表**：码值为字符串形态，内置码由 `GlobalErrorCodeConstants`
常量类定义并经 `ConstantsErrorCodeProvider` 注册进错误码注册表（i18n 解析见
[错误码与国际化](i18n.md)）。

## 分配规则（区间表）

| 区间 | 归属 | 规则 |
|------|------|------|
| `0` | 框架保留 | 唯一成功码，`ApiResult.success()` 专用 |
| `1 ~ 999` | 框架保留（系统级） | 对齐 HTTP 语义，见下表；**业务方不得新增此段** |
| `1000 ~ 999,999,999` | 预留禁用区 | 当前未使用，禁止占用（为未来系统级扩展保留） |
| `1,000,000,000 ~ 1,999,999,999` | 业务级 | 业务方错误码（10 位数值，`10` 开头），双轨登记（见 i18n 页） |
| `MUYI_` 前缀 | 框架保留 | 字符串码保留前缀，业务方禁用 |

业务模块码建议段内规划：`10 + 模块号(3) + 子域(3) + 序号(3)`，例如 `1001001001`
（模块 001 / 子域 001 / 序号 001）。

## 框架内置码（12 个）

| 码值 | 常量 | 默认文案 | 语义 |
|------|------|---------|------|
| `0` | `SUCCESS` | 成功 | 唯一成功码 |
| `400` | `BAD_REQUEST` | 请求参数不正确 | 客户端错误段 |
| `401` | `UNAUTHORIZED` | 账号未登录 | 客户端错误段 |
| `403` | `FORBIDDEN` | 没有该操作权限 | 客户端错误段 |
| `404` | `NOT_FOUND` | 请求未找到 | 客户端错误段 |
| `405` | `METHOD_NOT_ALLOWED` | 请求方法不正确 | 客户端错误段 |
| `423` | `LOCKED` | 请求失败，请稍后重试 | 客户端错误段 |
| `429` | `TOO_MANY_REQUESTS` | 请求过于频繁，请稍后重试 | 客户端错误段 |
| `500` | `INTERNAL_SERVER_ERROR` | 系统异常 | 服务端错误段（兜底） |
| `501` | `NOT_IMPLEMENTED` | 功能未实现/未开启 | 服务端错误段 |
| `502` | `ERROR_CONFIGURATION` | 错误的配置项 | 服务端错误段 |
| `999` | `UNKNOWN` | 未知错误 | 未归类的框架兜底 |

!!! note "历史沿革"

    原 `900 重复请求`、`901 演示拒绝` 因框架与模块内无任何调用方，已于重构阶段删除
    （业务侧幂等/限流语义请放入业务码段自定义）。

!!! note "码值对齐 HTTP 是命名约定，不是响应语义"

    `1 ~ 999` 段借用 HTTP 状态码的**命名**表达系统级错误分类，但它本质是
    **业务错误码命名空间**（字符串形态，即 `ApiResult.code`），与接口响应的
    HTTP 状态码**不等价**——网关、监控与客户端分支应以 `code` 语义为准，不要
    以内置码值反推传输层状态。例如 `502 ERROR_CONFIGURATION` 指"框架内部配置
    错误"，与 HTTP 502 Bad Gateway（上游网关错误）语义无关。

## 引用与登记

```java
// 常量形态（推荐，IDE 可追溯）：
throw ServiceExceptionUtil.exception(GlobalErrorCodeConstants.BAD_REQUEST);

// 注册表 i18n 解析（按请求 locale 重解文案）由异常处理器自动完成，
// 业务码的登记与多语言文案见《错误码与国际化》。
```

!!! warning "禁止 implements ErrorCode"

    `ErrorCode` 是值对象（不可变），只可构造引用，**不得作为接口实现**。
